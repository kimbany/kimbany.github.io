# 스마트스토어 리뷰 수집기

스마트스토어/브랜드스토어 **상품 링크만 붙여넣으면** 리뷰를 모아서
별점 분포 · 월별 추이 · 자주 나온 단어 · 옵션별 분포까지 정리해 보여준다. CSV/JSON 내보내기 지원.

> 배포 경로: **https://kimbany.github.io/smartstore-review/**

## 구성

```
smartstore-review/
├── index.html   # 수집기 본체 (단일 HTML, Tailwind CDN)
├── worker.js    # Cloudflare Workers 프록시 (선택 — 프록시 모드용)
└── README.md
```

## 두 가지 사용법

브라우저는 보안(CORS) 때문에 다른 도메인(네이버)을 직접 부를 수 없다. 그래서 방법이 둘이다.

### A. 북마클릿 모드 — 배포 없이 바로 사용 (추천)

상품 페이지 **안에서** 실행되므로 CORS가 아예 없고, 내 브라우저 IP로 나가니 차단 위험도 가장 낮다.

1. 수집기 페이지에서 **[북마클릿 모드]** 클릭
2. **📥 리뷰수집** 링크를 북마크바로 **드래그** (드래그가 막히면 `[코드 복사]` → 새 북마크 만들고 URL 칸에 붙여넣기)
3. 스마트스토어 **상품 페이지**를 열고 그 북마크를 클릭
4. 가져올 페이지 수 입력 → 우측 하단에 진행률 표시 → 끝나면 결과 JSON이 **클립보드에 복사됨**
5. 수집기 페이지의 붙여넣기 칸에 `Ctrl+V` → **[불러오기]**

> 4번에서 "**[리뷰] 탭을 눌러주세요**"가 뜨면 페이지의 리뷰 탭을 클릭하면 된다.
> 리뷰가 이미 열려 있으면 새 요청이 안 나가므로 **정렬을 바꾸거나 2페이지**를 누르면 된다.
> 클립보드 복사가 막힌 브라우저라면 콘솔(F12)의 `ssReviews` 변수에 같은 값이 들어있다.

#### 북마클릿이 리뷰를 찾는 순서

1. **직접 호출** — `__PRELOADED_STATE__`에서 뽑은 ID로 알려진 엔드포인트를 때린다. 성공하면 바로 끝.
2. **요청 가로채기** — 실패하면 `fetch`/`XMLHttpRequest`를 잠시 후킹하고 사용자가 리뷰 탭을 누르길 기다린다.
   페이지가 **실제로 보내는 리뷰 요청**을 붙잡아 그 요청의 페이지 번호만 바꿔가며 재사용한다.
   주소·파라미터 이름(`page` / `pageNo` / `pageNumber` …)이 뭐든 따라가므로 **네이버가 스펙을 바꿔도 계속 동작한다.**
3. **진단 리포트** — 둘 다 실패하면 시도한 주소·HTTP 상태·응답 앞부분을 담은 JSON을 클립보드에 복사한다
   (콘솔 변수 `ssDiag`). 이걸 붙여넣으면 원인을 특정할 수 있다.

같은 페이지가 반복해서 오면(페이지 파라미터를 못 찾은 경우) 중복을 감지해 그 자리에서 멈춘다.

### B. 프록시 모드 — 링크만 붙여넣고 자동 수집

1. dash.cloudflare.com → Workers & Pages → Create Worker (예: `ss-review`)
2. "Edit code" → 이 폴더의 `worker.js` 내용 붙여넣기 → Save and Deploy
3. Settings → Variables → `ALLOWED_ORIGINS` = `https://kimbany.github.io`
4. 배포 주소 복사 → 수집기 페이지 **⚙ 설정**에 붙여넣고 **저장** → **연결 확인**
5. 이후에는 상품 링크 붙여넣고 **[리뷰 가져오기]** 만 누르면 된다

> **API 키가 필요 없다.** 네이버 로그인 없이 공개된 리뷰만 읽는다.

## 지원 링크 형태

- `https://smartstore.naver.com/{스토어}/products/{상품번호}`
- `https://m.smartstore.naver.com/...` (자동으로 PC 주소로 변환)
- `https://brand.naver.com/{브랜드}/products/{상품번호}`
- 뒤에 붙는 `?NaPm=...` 같은 추적 파라미터는 알아서 제거됨

## 동작 방식

```
[상품 페이지 HTML]  →  window.__PRELOADED_STATE__ 파싱
                          ↓  channelNo / productNo / originProductNo / merchantNo
[리뷰 API]  /i/v2/channels/{ch}/products/{no}/contents/reviews   (1순위)
            /i/v1/contents/reviews/query-pages                   (2순위)
                          ↓
              공통 스키마로 정규화 → 화면 + CSV/JSON
```

네이버가 내부 API 스펙을 자주 바꾸므로, **키 이름을 하드코딩하지 않고**
객체 트리를 훑어 필요한 값을 찾는다(`findProductNode` / `deepFind` / `pickReviewArray`).
엔드포인트도 후보를 순서대로 시도해 첫 성공을 쓴다. 한쪽이 막혀도 다른 쪽으로 넘어간다.

## 화면에서 보는 것

| 영역 | 내용 |
|---|---|
| 상품 카드 | 썸네일 · 스토어명 · 평균 별점 · 전체 리뷰수 · 수집 건수 · 사진리뷰 비율 |
| 별점 분포 | ★1~5 건수/비율 막대 |
| 월별 리뷰 수 | 최근 12개월 추이 (판매 흐름 대리 지표) |
| 자주 나온 단어 | 조사 제거 + 불용어 필터 후 상위 24개, 클릭하면 해당 리뷰만 필터 |
| 옵션 분포 | 리뷰에 찍힌 옵션 Top 10 — 어떤 옵션이 많이 팔렸는지 |
| 리뷰 목록 | 별점·날짜·작성자·옵션·본문·첨부사진·판매자 답변 |
| 필터 | 별점 다중선택 / 사진리뷰만 / 내용 검색 / 6가지 정렬 |
| 내보내기 | CSV(엑셀용 BOM 포함) · JSON — **현재 필터된 결과만** 저장 |

## 한계 / 주의

- **비공식 내부 API**다. 네이버가 스펙을 바꾸면 멈출 수 있고, 그때는 `worker.js`의
  `reviewCandidates()`에 새 엔드포인트를 후보로 추가하면 된다.
- 프록시 모드는 **Cloudflare IP로 나가서 차단될 수 있다**(상품 페이지가 안 열리면 그 경우).
  이때 북마클릿 모드로 넘어가면 대부분 해결된다.
- 페이지 간 250ms 간격을 두고 순차 호출한다. **간격을 줄이거나 대량 반복 수집하지 말 것** — 차단 사유가 된다.
- 리뷰 작성자 ID는 네이버가 이미 마스킹한 값(`abc***`)이 그대로 온다.
  수집한 리뷰는 **본인 상품 분석·경쟁 조사 용도**로만 쓰고 재배포하지 말 것.
- 정렬 옵션은 네이버가 주는 순서를 그대로 따른다. "랭킹순"은 네이버 자체 기준이라 재현이 안 될 수 있다.
- 한 번에 최대 50페이지(1,000건)까지만 요청되도록 상한을 뒀다.
