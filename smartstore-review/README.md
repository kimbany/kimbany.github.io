# 스마트스토어 리뷰 수집기

스마트스토어/브랜드스토어 **상품 링크만 붙여넣으면** 리뷰와 상품 문의(Q&A)를 모아서
별점 분포 · 월별 추이 · 자주 나온 단어 · 옵션별 분포까지 정리해 보여준다.
**구글 시트로 바로 붙여넣기**, 리뷰 사진 일괄 다운로드, CSV/JSON 내보내기 지원.

> 배포 경로: **https://kimbany.github.io/smartstore-review/**

## 구성

```
smartstore-review/
├── index.html   # 수집기 본체 (단일 HTML, Tailwind CDN)
├── worker.js    # Cloudflare Workers 프록시 (선택 — 프록시 모드용)
└── README.md
```

## 두 가지 사용법

브라우저는 보안(CORS) 때문에 다른 도메인(네이버)을 직접 부를 수 없다. 그래서 방법이 둘이다.

### A. 북마클릿 모드 — 배포 없이 바로 사용 (추천)

상품 페이지 **안에서** 실행되므로 CORS가 아예 없고, 내 브라우저 IP로 나가니 차단 위험도 가장 낮다.

1. 수집기 페이지에서 **[북마클릿 모드]** 클릭
2. **📥 리뷰수집** 링크를 북마크바로 **드래그** (드래그가 막히면 `[코드 복사]` → 새 북마크 만들고 URL 칸에 붙여넣기)
3. 스마트스토어 **상품 페이지**를 열고 그 북마크를 클릭
4. **무엇을 가져올지** 선택

   | 번호 | 수집 대상 |
   |---|---|
   | `1` | 리뷰 (텍스트만) |
   | `2` | 리뷰 (사진까지) |
   | `3` | 문의(Q&A)만 |
   | `4` | 리뷰(텍스트) + 문의 |
   | `5` | 리뷰(사진까지) + 문의 |

   사진은 리뷰 1건당 여러 장이라 양이 크게 늘어난다. 텍스트만 필요하면 `1`·`4`를 고르면
   수집도 빠르고 결과 JSON도 가벼워진다(사진 미수집이면 상품 카드에 `미수집`으로 표시된다).
5. 가져올 페이지 수 입력 → 우측 하단에 진행률 표시 → 끝나면 결과 JSON이 **클립보드에 복사됨**
6. 수집기 페이지의 붙여넣기 칸에 `Ctrl+V` → **[불러오기]**

> 중간에 "**[리뷰] 탭을 눌러주세요**"(또는 **[문의] 탭**)가 뜨면 그 탭을 클릭하면 된다.
> 이미 열려 있으면 새 요청이 안 나가므로 **정렬을 바꾸거나 2페이지**를 누르면 된다.
> 클립보드 복사가 막힌 브라우저라면 콘솔(F12)의 `ssReviews` 변수에 같은 값이 들어있다.

#### 북마클릿이 데이터를 찾는 순서

1. **직접 호출** — `__PRELOADED_STATE__`에서 뽑은 ID로 알려진 엔드포인트를 때린다. 성공하면 바로 끝.
2. **요청 가로채기** — 실패하면 `fetch`/`XMLHttpRequest`를 잠시 후킹하고 사용자가 탭을 누르길 기다린다.
   페이지가 **실제로 보내는 요청**을 붙잡아 그 요청의 페이지 번호만 바꿔가며 재사용한다.
   - **주소 이름으로 거르지 않는다.** 경로에 `review`/`qna`가 들어있든 말든 상관없이,
     **응답 모양**이 리뷰(별점+본문) 또는 문의(질문 필드)면 그게 우리가 찾던 요청이다.
   - 페이지 파라미터 이름(`page` / `pageNo` / `pageNumber` …)도 뭐든 따라간다.
   - 그래서 **네이버가 스펙을 바꿔도 계속 동작한다.**
3. **진단 리포트** — 실패하면 시도한 주소·HTTP 상태·응답 앞부분을 담은 JSON을 남긴다
   (콘솔 변수 `ssDiag`). 이걸 붙여넣으면 원인을 특정할 수 있다.

같은 페이지가 반복해서 오면(페이지 파라미터를 못 찾은 경우) 중복을 감지해 그 자리에서 멈춘다.

#### 부분 실패 — 조용히 넘어가지 않는다

"리뷰는 됐는데 문의는 안 옴" 같은 경우가 제일 헷갈린다. 그래서 실패한 쪽이 있으면:

- 북마클릿 배너가 **"⚠ 문의는 못 가져왔습니다"**라고 알려준다.
- 결과 JSON에 `diag`가 **함께 담겨서** 복사된다. 따로 뭘 더 할 필요 없이
  평소처럼 수집기 페이지에 붙여넣으면 **주황색 경고 패널**이 뜨고 진단 내용이 보인다.
- 그 안에는 탭을 누르는 동안 **오간 JSON 응답 목록**이 들어 있다 —
  주소 · 최상위 키 · 배열 길이 · **배열 항목의 키 이름**. 같은 요청은 한 번만 기록한다.
  이 키 이름들만 있으면 어떤 응답이 문의 목록인지 특정해서 맞춰 고칠 수 있다.
- 기록이 **0건**이면 탭을 안 눌렀거나, 그 상품에 문의 영역 자체가 없다는 뜻이다.

### B. 프록시 모드 — 링크만 붙여넣고 자동 수집

1. dash.cloudflare.com → Workers & Pages → Create Worker (예: `ss-review`)
2. "Edit code" → 이 폴더의 `worker.js` 내용 붙여넣기 → Save and Deploy
3. Settings → Variables → `ALLOWED_ORIGINS` = `https://kimbany.github.io`

> 북마클릿 모드를 쓰더라도 Worker 주소를 등록해 두면 **리뷰 사진 다운로드**가 훨씬 안정적이다
> (`/img` 엔드포인트가 네이버 이미지에 CORS 헤더를 붙여준다).
4. 배포 주소 복사 → 수집기 페이지 **⚙ 설정**에 붙여넣고 **저장** → **연결 확인**
5. 이후에는 상품 링크 붙여넣고 **[리뷰 가져오기]** 만 누르면 된다

> **API 키가 필요 없다.** 네이버 로그인 없이 공개된 리뷰만 읽는다.

## 지원 링크 형태

- `https://smartstore.naver.com/{스토어}/products/{상품번호}`
- `https://m.smartstore.naver.com/...` (자동으로 PC 주소로 변환)
- `https://brand.naver.com/{브랜드}/products/{상품번호}`
- 뒤에 붙는 `?NaPm=...` 같은 추적 파라미터는 알아서 제거됨

## 동작 방식

```
[상품 페이지 HTML]  →  window.__PRELOADED_STATE__ 파싱
                          ↓  channelNo / productNo / originProductNo / merchantNo
[리뷰 API]  /i/v2/channels/{ch}/products/{no}/contents/reviews   (1순위)
            /i/v1/contents/reviews/query-pages                   (2순위)
                          ↓
              공통 스키마로 정규화 → 화면 + CSV/JSON
```

네이버가 내부 API 스펙을 자주 바꾸므로, **키 이름을 하드코딩하지 않고**
객체 트리를 훑어 필요한 값을 찾는다(`findProductNode` / `deepFind` / `pickReviewArray`).
엔드포인트도 후보를 순서대로 시도해 첫 성공을 쓴다. 한쪽이 막혀도 다른 쪽으로 넘어간다.

## 화면에서 보는 것

| 영역 | 내용 |
|---|---|
| 상품 카드 | 썸네일 · 스토어명 · 평균 별점 · 전체 리뷰수 · 수집 건수 · 사진리뷰 비율 |
| 별점 분포 | ★1~5 건수/비율 막대 |
| 월별 리뷰 수 | 최근 12개월 추이 (판매 흐름 대리 지표) |
| 자주 나온 단어 | 조사 제거 + 불용어 필터 후 상위 24개, 클릭하면 해당 리뷰만 필터 |
| 옵션 분포 | 리뷰에 찍힌 옵션 Top 10 — 어떤 옵션이 많이 팔렸는지 |
| **리뷰 / 문의 탭** | 사진 갤러리 아래에서 탭으로 갈라 본다. 각 탭에 **자체 구글 시트 복사 버튼** |
| 리뷰 목록 | 별점·날짜·작성자·옵션·본문·첨부사진·**판매자 답변** |
| 필터 | 별점 다중선택 / 사진리뷰만 / **판매자 답변만** / 내용 검색 / 6가지 정렬 |
| **상품 문의(Q&A)** | 답변률·미답변만 보기·검색, 질문/답변 나란히 |
| **구글 시트로 복사** | 클립보드에 표로 올려 시트에 바로 붙여넣기 (리뷰·문의 각각) |
| **리뷰 사진** | 필터에 걸린 리뷰의 사진을 격자로 모아 보기 · 폴더에 저장 / 전부 다운로드 / URL 목록 복사 |
| 내보내기 | CSV(엑셀용 BOM 포함) · JSON — **현재 필터된 결과만** 저장 |

### 리뷰 / 문의 탭

수집 결과는 **사진 갤러리 아래에서 두 탭**으로 갈린다.

- **리뷰** 탭 — 필터·정렬·리뷰 목록·CSV/JSON, 그리고 **구글 시트로 복사**
- **문의** 탭 — 답변률·미답변만·검색·문의 목록, 그리고 **자체 구글 시트로 복사**

탭 버튼에 각 건수가 붙고, 데이터가 없는 쪽은 눌리지 않는다. 한쪽만 수집했으면
그 탭이 자동으로 열린다. 사진 갤러리는 리뷰 쪽 자료라 문의 탭에서는 감춰진다.
상품 카드·별점 분포·키워드 같은 요약은 탭 위에 그대로 남아 항상 보인다.

### 구글 시트로 복사

CSV 파일을 거쳐 가져오기 하는 것보다 **클립보드가 빠르고 정확하다.** 버튼 하나로
클립보드에 **두 가지 형식을 동시에** 올린다.

| 형식 | 역할 |
|---|---|
| `text/html` `<table>` | 구글 시트가 우선 사용. **셀 안의 줄바꿈까지 그대로 살아난다** |
| `text/plain` TSV(탭 구분) | 위를 못 읽는 환경의 폴백. 줄바꿈은 공백으로 눕힌다 |

시트에서 **A1 클릭 → `Ctrl+V`** 하면 열이 정확히 나뉜다. 리뷰 본문에 쉼표·따옴표·줄바꿈이
섞여 있어도 CSV처럼 열이 밀리지 않는다. 클립보드 권한이 막힌 브라우저에서는
TSV가 담긴 텍스트박스가 대신 열린다(전체 선택된 상태).

**현재 필터에 걸린 것만** 복사되므로 "★1~2 + 사진리뷰만" 같은 조건을 걸고 그대로 시트에 넘길 수 있다.
`상품명` 열이 있어 여러 상품을 같은 시트에 계속 이어붙여도 구분된다.

### 상품 문의 (Q&A)

- 북마클릿 실행 시 `2`(문의) 또는 `3`(둘 다)을 고르면 함께 수집한다.
- 리뷰와 마찬가지로 **응답 모양으로 판별**한다 — `question` / `questionContent` /
  `inquiryContent` / `qnaContent` 중 하나를 가진 객체를 문의로 본다.
- 그걸로도 못 잡으면 **점수제로 고른다.** 응답 안의 모든 "객체 배열"을 꺼내
  키 이름이 `question|inquiry|qna` 계열이면 +2, `answer|reply` 계열이면 +1,
  리뷰 계열(`reviewScore` 등)이면 -5 를 줘서 가장 문의스러운 배열을 집는다.
  덕분에 `qnaNo` / `inqTitle` / `ansBody` / `regDt` 처럼 **처음 보는 필드명이어도** 정리해낸다.
- 본문·답변을 뽑을 때도 필드명을 3단으로 시도한다.
  1. 알려진 이름 (`question` · `answerContent` …)
  2. 키 패턴 (`question|inquiry|qna|title|content|body|text|subject` / `answer|reply|ans`),
     중첩된 객체는 한 겹 안쪽(`.content` · `.text` · `.body`)까지
  3. **그래도 없으면 항목에서 가장 긴 사람 글**을 본문으로 본다
     (URL·날짜·숫자·마스킹된 ID는 제외)
- 그래도 실패하면 **조용히 넘어가지 않는다** — 아래 "부분 실패" 참고.

#### 건수는 잡혔는데 본문이 비어 있으면

목록 API가 본문을 안 내려주거나 필드명을 끝내 못 맞힌 경우다. 이때는
**원본 항목 3개를 그대로 진단에 담는다**(긴 문자열은 200자로 자름).
수집기에 붙여넣으면 "내용이 비어 있습니다" 패널에 그 원본이 보인다 —
필드 이름만 확인하면 맞춰 고칠 수 있다. 리뷰도 같은 방식으로 감시한다.

#### 자동 클릭은 "보기 탭"에만

탭을 자동으로 눌러 요청을 유도하는데, **`문의하기` · `리뷰쓰기` 같은 동작 버튼은 절대 누르지 않는다.**
누르면 문의 작성창이 열리거나 글이 등록될 수 있다. 후보에서 빼는 기준:

- 라벨에 `하기 / 쓰기 / 작성 / 등록 / 신청 / 신고 / 톡톡 / 채팅`이 들어가면 제외
  (`문의` · `구매평` 같은 정상 탭 이름은 그대로 둔다)
- 다른 페이지로 이동하는 링크(`href`가 `#`로 시작하지 않는 `<a>`) 제외
- 화면에 안 보이는 요소 제외
- 남은 후보 중 `role="tab"` · 앵커 · `리뷰 (25)`처럼 개수가 붙은 것을 우선

**탭 자체가 없으면 그 상품엔 그 영역이 없는 것**으로 보고 90초씩 기다리지 않는다(약 18초 후 종료).

#### 이 상품 것이 맞는지 확인한다

상품 페이지에는 **스토어 전체 리뷰 위젯**처럼 다른 상품의 리뷰를 부르는 요청도 섞여 있다.
그런 걸 잡으면 복숭아 상품인데 사과 리뷰가 모이는 일이 생긴다. 그래서 잡은 요청의
주소·본문에 **이 상품 번호(`productNo` / `originProductNo` / `channelNo`)가 들어 있는지** 본다.

- 들어 있으면 그대로 채택 (`scope: "product"`)
- 없으면 일단 보류하고 **6초 더** 기다려 상품 번호가 붙은 요청을 찾는다
- 끝내 못 찾으면 보류분을 쓰되 `scope: "unverified"`로 표시하고,
  수집기 상품 카드에 **"다른 상품이 섞였을 수 있습니다"** 경고를 띄운다

#### 문의가 없는 상품

문의가 없는 것은 실패가 아니다. 그래서:

- 배너: **"이 상품에는 문의가 없습니다"** (경고 아님), 리뷰 수집 결과는 그대로 복사된다
- 수집기 화면: 회색 안내 한 줄만 (`상품 문의 없음`), 진단 정보도 안 붙는다
- 문의만 요청했는데 없으면 그냥 "수집할 내용이 없어 종료합니다"로 끝난다

`qnaResult` 값으로 구분한다 — `ok`(수집됨) / `none`(없음) / `failed`(있는데 못 잡음).
- 정리해 보여주는 것: **답변률**, 미답변만 보기, 문의 검색, 질문/답변 나란히, 비밀글 표시.
- 답변 대기 중인 문의를 빠르게 훑는 용도. 시트 복사 / CSV 저장도 별도로 있다.

### 판매자 답변

리뷰에 달린 판매자 답변은 `mallReview` / `commentContent` / `sellerComment` 등
버전마다 자리가 다르다. **키 이름이 답변스러운 곳만** 훑어서 가져온다
(리뷰 본문을 답변으로 오인하지 않도록 값이 아니라 키로 판단). 상품 카드에 **답변률**이 뜨고,
`판매자 답변만` 필터와 CSV·시트의 `판매자답변` 열로 나간다.

### 리뷰 사진

- 사진 URL은 필드명(`attaches` / `reviewAttaches` / `mediaList` / `photoInfos` …)을 가리지 않고
  리뷰 객체 안의 **이미지처럼 생긴 문자열을 전부 훑어** 모은다. 프로필·아이콘 이미지는 제외하고,
  같은 사진의 리사이즈 변형(`?type=w120` 등)은 하나로 합친다.
- 저장할 때는 `?type=...`을 떼어 **원본 해상도**를 받는다.
- **폴더에 저장** — 크롬/엣지에서 폴더를 고르면 그 안에 바로 저장(권장).
  **전부 다운로드** — 브라우저 상관없이 하나씩 순차 저장.
- 파일명은 `review001_s5_2026-07-02.jpg` 형식. 한글 파일명은 브라우저가 무시하고
  전부 `download`로 저장해 버리는 경우가 있어 ASCII로 고정했다.
- 네이버 이미지 CDN은 CORS 헤더를 주지 않아 브라우저가 바이트를 못 읽는다. 그래서
  **Worker(`/img`) → 직접 → 공개 CORS 프록시** 순으로 시도한다.
  실패가 많으면 ⚙설정에 Worker 주소를 넣으면 대부분 해결된다.
- CSV에는 `사진수`·`사진URL` 열이 함께 나간다. `상품명` 열도 있어 여러 상품 CSV를
  엑셀에서 그대로 이어붙일 수 있다.

## 한계 / 주의

- **비공식 내부 API**다. 네이버가 스펙을 바꾸면 멈출 수 있고, 그때는 `worker.js`의
  `reviewCandidates()`에 새 엔드포인트를 후보로 추가하면 된다.
- 프록시 모드는 **Cloudflare IP로 나가서 차단될 수 있다**(상품 페이지가 안 열리면 그 경우).
  이때 북마클릿 모드로 넘어가면 대부분 해결된다.
- 페이지 간 250ms 간격을 두고 순차 호출한다. **간격을 줄이거나 대량 반복 수집하지 말 것** — 차단 사유가 된다.
- 리뷰 작성자 ID는 네이버가 이미 마스킹한 값(`abc***`)이 그대로 온다.
  수집한 리뷰는 **본인 상품 분석·경쟁 조사 용도**로만 쓰고 재배포하지 말 것.
- 정렬 옵션은 네이버가 주는 순서를 그대로 따른다. "랭킹순"은 네이버 자체 기준이라 재현이 안 될 수 있다.
- 한 번에 최대 50페이지(1,000건)까지만 요청되도록 상한을 뒀다.

- 상품 문의는 **북마클릿 모드 기준**이다. 프록시(Worker)에도 후보 주소를 넣어뒀지만
  확실한 공개 엔드포인트가 아니라 실패할 수 있다.
- 스마트스토어는 문의를 **네이버 톡톡으로만 받는 상품**이 많다. 그런 상품엔 문의 탭이
  없으므로 "문의 없음"으로 끝난다 — 도구 문제가 아니다.
- 비밀글 문의는 목록에 뜨더라도 내용이 비어 있을 수 있다(네이버가 안 내려줌).
