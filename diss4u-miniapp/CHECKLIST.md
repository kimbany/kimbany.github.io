공식 체크리스트를 항목별로 받아 코드와 대조한 결과다.
출처: https://developers-apps-in-toss.toss.im/checklist/app-nongame.html

`✅` 코드로 확인 · `🔧` 이번에 고침 · `📱` 실기기에서만 확인 가능 · `⛔` 콘솔 작업 필요

## 이번 점검에서 고친 것 (4건)

### 🔧 자체 뒤로가기 버튼이 토스 내비바와 중복

> "토스 내비게이션 바의 뒤로가기 버튼과 미니앱에서 자체 구현한 뒤로가기 버튼이
> 동시에 보이지 않아요."

화면 5곳에 `← 뒤로` 버튼을 직접 넣어뒀었다. 토스가 내비게이션 바에 뒤로가기를
제공하므로 두 개가 같이 보인다.

전부 걷어내고, 토스 내비바의 뒤로가기를 `graniteEvent.backEvent` 로 받아
내부 화면 스택에 연결했다(`lib/shell.js`).

히스토리를 안 쓰기로 한 결정이 여기서 값을 했다. `pushState` 로 화면을 쌓았다면
토스 뒤로가기와 브라우저 히스토리가 각자 움직여 어긋났을 것이다.

### 🔧 최초 화면에서 뒤로가기를 눌러도 안 나가짐

> "최초 화면에서 뒤로가기를 누르면 미니앱이 종료돼요."

되감을 화면이 없으면 홈으로 리셋만 하고 있었다. 이제 `Screen.close()` 로 나간다.
모달이 떠 있으면 모달부터 닫는다 — 뒤로가기 한 번에 두 단계가 사라지면 안 된다.

### 🔧 진입 직후 바텀시트가 자동으로 열림

> "미니앱에 들어오자마자 바텀시트가 자동으로 열리지 않아요."
> "특정 화면 전환 시 바텀시트로 사용자의 행동을 강제로 유도하지 않아요."

크레딧 소멸 임박 안내를 바텀시트로 만들어놨었다. 로그인 직후 `/me` 응답이 오면
바로 떠서 정면으로 걸린다.

홈 화면 위에 얹는 띠(배너)로 바꿨다. 읽고 닫을 수 있고 아무것도 막지 않는다.
같은 만료 건은 하루 한 번만 뜬다.

### 🔧 토스에서 로그인 연결을 끊어도 데이터가 남음

> "토스 앱에서 로그인 연결을 끊으면 사용자 데이터가 미니앱에 남아 있지 않아요."
> "토스 앱에서 로그인 연결을 끊은 뒤 미니앱에 다시 접속하면, 다시 로그인을
> 요청하는 약관 화면이 노출돼요."

Firebase 세션은 토스 연결과 별개로 살아 있다. 연결을 끊어도 미니앱만 보면
여전히 로그인 상태였다.

부팅할 때 `TossAuth.isIntegrated()` 로 대조해서, 끊겼으면 Firebase 로그아웃 +
곡 캐시를 비운다. 판단할 수 없을 때(구버전·브라우저)는 아무것도 하지 않는다 —
애매하다고 로그아웃시키면 멀쩡한 사용자를 쫓아낸다.

## 이미 지키고 있던 것

### 내비게이션 · UX
- ✅ 링크나 컴포넌트로 자사 서비스 이동이나 자사 앱 설치를 유도하지 않아요
      → 쿠팡 배너, 인스타/틱톡/유튜브 계정 링크, 외부 약관 링크를 전부 뺐다.
        약관·방침·환불정책은 `screens/legal.js` 로 앱 안에서 본다
- ✅ 모든 화면에서 사용자가 미니앱을 나갈 수 있는 방법이 명확해요
- ✅ CTA 버튼을 보면 다음에 어떤 행동이 일어날지 예측할 수 있어요
- ✅ Safe Area 를 침범하지 않아요 → `getSafeAreaInsets()` 를 첫 렌더 전에 CSS 변수로 심는다

### 화면
- ✅ 미니앱 테마는 라이트 모드로 구현돼 있어요
      → 원본이 전면 다크(`#0d0d10`)라 팔레트를 새로 짰다.
        OS 다크모드를 따라가지 않도록 `color-scheme: light` 를 못박았다
- ✅ 제스처 기반 확대·축소가 비활성화돼 있어요
      → viewport meta + `touch-action`. iOS 는 meta 의 `user-scalable=no` 를 무시한다
- ✅ 2초 이상 지연 금지 → 노래 생성(1~2분) 동안 퍼센트·경과초·단계 문구가 계속 움직인다

### 인앱 결제
- ✅ 인앱 결제를 진행할 때, 미니앱에서 재생 중인 음악은 일시 정지돼요
      → `lib/audio.js` 의 참조 카운트 suspend 게이트. 원본은 결과 화면을 벗어날 때만
        멈춰서, 결과 화면에 머문 채 열리는 충전 시트에서는 노래가 계속 흘렀다
- ✅ 결제에 실패했을 때, 사용자가 실패 사유를 인지할 수 있어요
- ✅ 인앱 결제창에서 취소를 선택하면 주문 화면으로 돌아가요
- ✅ 인앱 결제 상품에 대한 결제 내역을 사용자가 확인할 수 있어요 → `screens/credits.js`
- ✅ 토스페이 외의 다른 결제 수단은 제공하지 않아요 → PortOne·PayPal·카카오페이 전부 뺐다

### 인앱 광고
- ✅ 인앱 광고가 재생될 때, 미니앱에서 재생 중인 음악은 일시 정지돼요
- ✅ 인앱 광고 종료 후 미니앱 음악이 다시 재생돼요
      → 구간 진입 시 재생 중이었을 때만 재개한다
- ✅ 인앱 광고는 사전에 로딩돼 있어요. 광고 재생 시점에 실시간으로 로딩하지 않아요
      → `show()` 는 이미 로드된 광고가 있을 때만 뜨고, 없으면 조용히 넘어간다
- ✅ 인앱 광고는 인트로/로딩/컷신/팝업 모달 등 일시적인 화면에 노출되지 않아요
      → 아직 광고 호출 지점을 만들지 않았다. 붙일 때 이 조항을 지킬 것

### 로그인
- ✅ 토스 로그인이 아닌 자사 로그인이나 기타 로그인 방식은 제공하지 않아요
      → 구글·카카오 로그인과 `inappGuideModal` 을 뺐다.
        서버가 Firebase Custom Token 을 발급하지만 사용자에게 보이는 로그인은 토스뿐이다
- ✅ 어떤 서비스인지 알 수 있도록 인트로에서 서비스 설명을 제공해요
      → 로그인 게이트에 설명 문구가 있다

### 기술
- ✅ SSR 을 쓰지 않아요 → vite 정적 빌드(CSR)
- ✅ `eval` 을 쓰지 않아요 → 원본에도 없었다
- ✅ 모든 통신이 HTTPS 예요
- ✅ 번들이 압축 해제 기준 100MB 이하예요 → `diss4u.ait` 약 150KB
- ✅ 사용자 로그인 정보·결제 내역 등 민감 정보를 암호화해서 저장해요
      → 개인정보는 토스가 AES-256-GCM 으로 암호화해 내려주고, 서버에서만 복호화한다.
        복호화 키와 AAD 는 Render 환경변수에 둔다

### 콘텐츠
- ✅ 미니앱 문구에 비속어, 은어, 과도한 유행어가 포함되지 않아요
      → UI 문구에서 '디스·욕·까기' 를 뺐다.
        생성 가사는 `server-patch/profanity.js` 가 거른다(테스트 45케이스)
- ✅ 이용자 신고 수단이 있어요 → `ui/report.js` (결과 화면 하단)

## 실기기·콘솔에서만 확인 가능한 것

### 📱 실기기 샌드박스
- [ ] 미니앱이 정상적으로 열려요
- [ ] '앱 내 기능' 에 등록한 스킴이 정상적으로 연결돼요
- [ ] 앱 스킴으로 진입한 뒤, 뒤로가기 버튼이 정상적으로 작동해요
      → `lib/shell.js` 로 연결해뒀지만 실기기 확인 필요
- [ ] 앱 정보에 등록한 브랜드 로고와 미니앱 이름(국문)이 내비게이션바에 표시돼요
- [ ] 더보기 버튼(⋯)에서 토스 공통 기능(신고, 공유 등)이 정상 제공돼요
- [ ] 인스타 영상 생성 가부 (Canvas + MediaRecorder + AudioContext)
- [ ] 토스 앱에서 로그인 연결을 끊은 뒤 재접속 시 약관 화면이 다시 뜨는지

### ⛔ 콘솔 작업 후 확인
- [ ] 인앱 결제 주문 금액과 결제창 금액이 일치해요 → 상품 등록 후
- [ ] 인앱 결제가 완료된 뒤 결과가 정상 반영돼요 → mTLS 인증서 발급 후
- [ ] 인앱 결제 취소가 정상 처리돼요
- [ ] 기기를 바꿔도 기존 결제 데이터가 유지돼요 → `getPendingOrders` 복구 로직으로 대응
- [ ] 리워드 광고를 끝까지 보면 보상이 지급돼요 → `AD_GROUP_ID` 설정 후
- [ ] 배너 광고가 적절한 위치, 스크롤 가능한 화면에만 노출돼요 → 아직 배너 미도입
- [ ] 설정한 토스 로그인 약관 화면 URL 이 정상 노출돼요
