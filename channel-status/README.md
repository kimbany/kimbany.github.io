# 채널별 상품 판매상태 모니터링

여러 오픈마켓에 올려둔 제품이 채널마다 **지금 판매중인지 · 판매중지인지 · 품절인지 · 미등록인지**를
한 화면에서 확인합니다. 기준 단위는 **자체상품코드**입니다.

> 매출이나 주문 건수를 보는 도구가 아닙니다. 오직 등록된 제품 리스트의 상태만 봅니다.
> 매출 통합은 [`../sales-report/`](../sales-report/) 가 담당합니다.

👉 <https://invedory.com/channel-status/>

## 화면 4개

| 화면 | 무엇을 보나 | 기준 |
|---|---|---|
| **데일리 판매 현황** | 오늘 상태가 바뀐 제품 + 예약 알림 | 상품 기준 |
| **변동 현황** | 두 날짜를 비교한 변동 목록 | 채널 기준 |
| **채널 현황 › 채널별 현황** | 날짜 × 상품 × 채널 매트릭스 | 표 |
| **채널 현황 › 예약** | "언제 무엇을 바꿀지" 체크리스트 | — |
| **설정** | 채널 · 상품 마스터 · ID 매핑 · 수집 · 백업 | — |

## 지금 할 수 있는 것

- 자체상품코드 마스터 등록 (직접 입력 / CSV 일괄 업로드 / 내보내기)
- 채널 추가·삭제·활성 토글, 채널별 상태 표기 매핑
- 자체상품코드 ↔ 채널별 상품ID 매핑 (표에서 바로 수정)
- **CSV 로 상태 올리기** — 가로형·세로형 둘 다. 저장 전에 무엇이 바뀌는지 미리 보여줍니다
- 날짜별 스냅샷 누적, 하루 여러 번 수집(회차)
- 전일 대비 변동 자동 계산, 변동 유형별 색 구분
- 예약 등록·수정·삭제, 예약일 7일 전부터 D-day 알림
- JSON 백업 / 복원, 오래된 회차 정리

처음 열면 **데모 데이터**가 채워집니다. 실제로 쓰기 전에 `설정 › 기타 › 전체 초기화` 를 누르세요.

## 쓰는 순서

1. `설정 › 채널 관리` — 스펙의 10개 채널이 기본으로 들어 있습니다. 안 쓰는 채널은 비활성 처리
2. `설정 › 상품 마스터` — `samples/상품마스터.csv` 모양으로 자체상품코드를 올립니다
3. `설정 › 채널 상품ID 매핑` — 채널에 등록된 상품ID를 채웁니다. **비어 있으면 그 채널은 미등록**
4. 매일 `CSV 상태 업로드` — `samples/상태_가로형.csv` 모양으로 그날 상태를 올립니다
5. `데일리 판매 현황` 에서 무엇이 바뀌었는지 확인

## CSV 형식

첫 줄에 `자체상품코드` 열만 있으면 두 모양 다 받습니다.

```
가로형   자체상품코드,스스_MO,스스_GY,11번가,...
세로형   자체상품코드,채널,상태
```

- 채널 열 이름은 **화면 표기(`스스_MO`)** 든 **채널키(`ss_mo`)** 든 됩니다.
- **올린 칸만 갱신하고 나머지는 기존 상태를 유지합니다.** 한 채널만 올렸을 때
  나머지 채널이 통째로 미등록으로 뒤집히지 않게 하기 위해서입니다.
- 해석하지 못한 상태값은 **추측하지 않고** 미매핑으로 남깁니다.
  `설정 › 채널 관리` 하단에서 4가지 상태 중 하나로 직접 지정하세요.

## 데이터가 어디에 저장되나

지금은 **로컬 모드** — 이 브라우저의 `localStorage` 에만 저장됩니다 (키 `채널상태:v1`).
다른 기기와 공유하려면 `설정 › 기타` 에서 JSON 백업을 옮기거나,
`index.html` 상단의 `firebaseConfig` 를 채워 Firestore 로 전환하세요.
저장소 호출은 Firestore 와 같은 `(컬렉션, 문서ID)` 인터페이스로 짜여 있어 전환 시 화면 코드는 그대로입니다.

로컬 모드는 5MB 안팎이 한계라 스냅샷 70~80일이면 찹니다.
`설정 › 기타 › 오래된 회차 정리` 로 회차만 지우면 날짜별 대표 스냅샷은 남아 과거 조회가 계속 됩니다.

## API 자동 수집은 아직입니다

채널 API 로 상태를 자동으로 끌어오는 건 **6단계**이고 아직 붙이지 않았습니다.
10개 채널 중 절반 이상이 API 접근 승인에 걸려 있어서, 전체 화면이 CSV 만으로 먼저
돌아가는 게 안전하다고 판단했습니다. 채널별 사정은 `설정 › 데이터 수집` 화면과
[CLAUDE.md](CLAUDE.md) 에 정리해 두었습니다.

| 자동수집 | 채널 |
|---|---|
| 🟢 가능 | 스스_MO · 스스_GY · 11번가 |
| 🟡 신청 후 | 옥션 · 지마켓 · 토스_GY |
| 🟠 승인 필요 | SSG |
| 🔴 어려움 | 카카오_MO · 카카오_GY · 알리익스프레스 |

`worker/` 에 Cloudflare Workers 프록시 골격이 있습니다. 대시보드가 채널 API 를 직접 부를 수 없는 이유
(CORS · 시크릿 노출 · 네이버의 호출 IP 사전 등록)와 함께 주석으로 적어두었습니다.

**API 키·시크릿은 이 대시보드에 저장하지 않습니다.** GitHub Pages 위의 정적 페이지라
브라우저에 들어간 값은 곧 공개된 값입니다. 시크릿은 Worker 의 Secret 에 둡니다.

## 예약은 자동 반영이 아닙니다

예약은 **체크리스트**입니다. 날짜가 되면 데일리 화면 상단에 띄워줄 뿐,
채널에 자동으로 반영하지 않습니다. 실제 반영은 각 채널에 직접 들어가서 하시고,
처리한 뒤 `반영함` 을 눌러 완료 표시하세요.
