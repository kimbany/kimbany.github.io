# 최초 요청서 — 판매가 설정 도우미

작성일 2026-08-25. 아래 §1 은 받은 요청 원문, §2 는 착수 전 질문에 대한 확정 답변이다.
설계 판단이 갈릴 때는 §2 가 기준이다.

---

## §1. 요청 원문

판매가 설정 도우미 웹앱을 만들어줘.

### 기술 스택 — 기존 컨벤션 유지
- 단일 HTML 파일, 프레임워크와 번들러 없이
- Tailwind CSS CDN
- 채널/브랜드 설정값은 Firebase Firestore에 저장
- GitHub Pages 배포 기준
- 함수명과 주석은 한글로 작성

### 공통 규칙
1. 금액이나 퍼센트를 입력받는 모든 칸, 그리고 계산 결과를 보여주는 모든 곳에 "VAT 포함" 안내 문구를 표시할 것.
2. 용어는 "제품명"으로 통일. "상품명"이라는 표현은 화면 어디에도 쓰지 말 것.

### 메뉴 구조
- 판매가 (대메뉴)
  - 원가 계산 (중메뉴)
  - 판매가 계산 (중메뉴)
- 채널 기본설정 (대메뉴)
- 자사 브랜드 (대메뉴)

### 1. 판매가 > 판매가 계산
원가를 기준으로 "얼마에 팔면 되는지"를 역산해주는 화면.

입력 항목
- 제품명 : 텍스트 입력 (필수)
- 무게·수량 : 단위를 g / kg / 개 중에서 드롭다운으로 고른 뒤 숫자 입력 (필수)
- 입수량 : 숫자 범위 입력, n개 ~ n개 (선택)
- 원가 : 숫자 입력 (필수)
- 마진율 : 남기고 싶은 마진율 % 입력 (필수)
- 무료 택배비 여부 : 체크박스 (선택). 체크하면 판매가 계산에 반영됨

마진율 입력칸
- 기본 1개로 시작하되, 여러 마진율을 동시에 비교할 수 있도록 입력칸을 추가/삭제하는 버튼이 있어야 함.

계산 방식
- 채널 기본설정에 등록된 채널별 수수료 %를 각각 대입해서, 채널마다 판매가를 따로 계산한다.
- 각 채널에는 자사 브랜드가 연결되어 있고, 그 브랜드에 포장비가 있으면 그 금액도 원가에 더해서 계산한다.
- 무료 택배비에 체크한 경우 택배비도 원가에 더해서 계산한다.

결과 화면
- 채널별로 영수증처럼 카드가 나뉘어 보이도록 한다.
- 마진율 입력칸이 여러 개면, 한 채널 카드 안에서 마진율별로 구분해서 판매가를 각각 보여준다.
- 각 카드에는 원가, 포장비, 택배비, 수수료, 마진, 최종 판매가가 항목별로 다 보이게 한다.

### 2. 판매가 > 원가 계산
입고 단위와 판매 단위가 다를 때, 판매 기준으로 환산한 원가를 구하는 화면.
(예: 사과가 3kg 9,000원에 입고됐는데 나는 2kg 단위로 팔고 싶다 → 2kg 기준 원가가 얼마인지)

입력 항목
- 입고 제품명 : 텍스트 입력
- 입고 무게·수량 : 단위를 g / kg / 개 중 드롭다운으로 선택 후 숫자 입력. 선택한 단위에 따라 환산식이 자동으로 바뀌어야 함
- 입고가 : 숫자 입력 (원)
- 판매하려는 기준 단위·수량 입력칸

기능
- "판매가 계산으로 보내기" 버튼이 있어야 한다.
- 이 버튼을 누르면 판매가 계산 화면의 제품명, 원가, 무게·수량 칸에 값이 자동으로 채워진다.

### 3. 채널 기본설정
- 채널 추가 / 수정 / 삭제 가능
- 입력 항목 : 채널명(텍스트), 채널 수수료(% 입력), 채널 브랜드(자사 브랜드 메뉴에 등록된 브랜드 중 드롭다운 선택)

### 4. 자사 브랜드
- 브랜드 추가 / 수정 / 삭제 가능
- 입력 항목 : 브랜드명(텍스트), 포장비(원 단위 숫자)

### 진행 방식
- 질문에 대한 답을 받은 뒤, CLAUDE.md와 INITIAL_PROMPT.md를 먼저 작성하고 시작해줘.
- 메뉴 구조와 화면 뼈대 → 채널/브랜드 설정 저장 → 계산 로직 → 결과 카드 순서로 만들어줘.

## §2. 착수 전 질문과 확정 답변

### Q1. 판매가 역산 공식 — 마진율을 판매가 대비로 볼지 원가 대비로 볼지

**답: 판매가 대비.** 제안한 공식 그대로 간다.

```
판매가 = (원가 + 포장비 + 택배비) ÷ (1 − 수수료율 − 마진율)
```

### Q2. 택배비 금액을 어디에 설정할지

**답 (원문):**

> 자사 브랜드 메뉴에서 하위 메뉴를 2개로 쪼개줘 브랜드 / 택배 로
> 그래서 브랜드 내용은 원래 내가 입력했던 브랜드 내용 유지해주고,
> 택배 부분에서는 추가, 수정, 삭제 기능 넣어주고 그중에서도 라디오 박스로해서
> 기본 택배비가 무엇인지 선택하고 저장할수 있게해줘,
> 택배비 데이터 입력란을 만들어줘 택배비 데이터 입력에는 택배비 n원 을 기입할수 있게해주고
>
> 그러면 판매가 기본 입력란에서 택배비는 체크박스로 말고
> 택배비 데이터 입력한 거 중에 어떤걸로 가져와서 계산할지 드롭박스 선택으로해줘

→ §1 의 "무료 택배비 : 체크박스" 는 **드롭다운으로 대체**된다.
→ 자사 브랜드 대메뉴에 중메뉴 2개(브랜드 / 택배)가 생긴다.

### Q3. 입수량이 계산에 어떻게 반영돼야 하는지

**답: 원가는 판매 1건 기준, 입수량은 표시용.**
입수량으로 나누지 않는다. 단위 환산은 "원가 계산" 화면에서 끝내고 넘어온다.

### Q4. 입력 원가의 VAT 기준과 결과 판매가의 VAT 처리

**답: 전부 VAT 포함 기준으로 통일.** 별도 환산 없음.

### Q5. 판매가 끝자리 반올림 규칙

**답 (원문):**

> 판매가 결과 값에는 너가 추천해준 100원 단위 올림 으로 보여주면서
> 하단에 작게 최대한 800원 단위로 끝나는 가격도 나오게해줘
> 13450원 이 나온다면 12800원이 아니라 13800원으로 / 14110원 이 나온다면 13800원이 아니라 14800원으로

→ 대표가 = 100원 올림, 보조 표기 = 800원으로 끝나는 가격(올림 방향).

# 추가 요청서 — 제품코드 메뉴 (2026-08-27)

## §4. 요청 원문

판매가 설정 도우미에 "제품코드" 대메뉴를 추가해줘.

### 기존 규칙 그대로 유지
- 단일 HTML 파일, 프레임워크·번들러 없이, Tailwind CSS CDN
- 데이터는 Firebase Firestore에 저장
- 함수명과 주석은 한글로 작성
- 금액·퍼센트가 나오는 곳에는 "VAT 포함" 안내 표시
- 용어는 "제품"으로 통일. "상품"이라는 표현은 화면 어디에도 쓰지 말 것

### 메뉴 구조
- 판매가 / 원가 계산 / 판매가 계산
- **제품코드 ← 이번에 추가** / 제품코드 목록 / 제품코드 생성 / 분류
- 채널 기본설정
- 자사 브랜드

만드는 순서는 분류 → 제품코드 생성 → 제품코드 목록 순.
앞 화면에서 등록한 값을 뒷 화면이 가져다 쓰는 구조라서.

### 1. 제품코드 > 분류

코드를 조합할 재료를 등록해두는 화면. 추가·수정·삭제가 다 가능해야 함.

생성 버튼 4개
1. **대분류 생성** — 대분류명 / 대분류 코드 / 옵션분류명 / 옵션분류 코드.
   대분류와 옵션분류는 한 세트로 묶어서 등록한다
2. **중량·수량 생성** — 숫자 입력 + 단위 드롭다운 (G / EA)
3. **입수량 생성** — n개 ~ n개 범위 입력
4. **브랜드 생성** — 브랜드명 / 브랜드 코드

화면 표시 — 대분류 / 중량·수량 / 입수량 / 브랜드 네 그룹으로 나눠서 목록을 보여줄 것

### 2. 제품코드 > 제품코드 생성

코드를 만들기만 하는 화면. 만든 코드는 제품코드 목록으로 넘어가서 거기서 보인다.

- 드롭다운 5개 : 브랜드, 대분류, 옵션분류, 중량·수량, 입수량
- 분류 메뉴에 등록된 값만 선택할 수 있게 할 것
- 옵션분류 드롭다운에는 선택한 대분류에 묶여 있는 것만 뜨게 할 것

저장하면
- 코드 순서는 브랜드 코드 - 대분류 코드 - 옵션분류 코드 - 중량·수량 - 입수량
- 두 가지 형태로 조합해서 보여준다
  - 구분형코드 : `MO-GP-SH-2000G-0203`
  - 연속형코드 : `MOGPSH2000G0203`

### 3. 제품코드 > 제품코드 목록

생성된 코드를 보고, 검색하고, 복사하는 화면.
구분형과 연속형 두 가지가 같이 보이고 각각 바로 복사할 수 있어야 함.

- **분류로 검색** — 제품분류(대분류+옵션분류) / 중량·수량(G·EA) / 브랜드.
  다 고르면 모두 만족하는 것만, 하나만 고르면 그 조건에만 맞으면 나온다
- **키워드로 검색** — 분류명, 생성된 코드, 옵션분류, 브랜드 중 어디에든 걸리면
- **복사** — 상단에 체크박스로 여러 개 골라 한 번에 복사하는 버튼.
  구분형/연속형 중 고를 수 있게. 체크를 안 해도 각 행마다 개별 복사 버튼이 따로 있어야 함
- **목록 표시** — 행마다 수정/삭제 버튼, 생성된 날짜를 작게 표시,
  정렬 전환(제품코드 기준 / 생성 날짜 기준, 각각 오름차순·내림차순)

## §5. 착수 전 질문과 확정 답변

### Q1. 브랜드가 「자사 브랜드」와 「분류」 두 군데 생기는 문제

**답: 자사 브랜드에 브랜드 코드 칸을 추가해 한 곳에서 관리한다.**
분류 화면의 브랜드 그룹은 같은 목록을 읽고 쓰며, 거기서 등록해도 자사 브랜드에 함께 들어간다.

### Q2. 입수량 코드 자릿수 — 0203 이 "2개~3개" 를 두 자리씩 붙인 것인지

**답: 맞다. 두 자리 고정, 0~99 만 허용.** 100 이상은 등록할 때 막는다.

### Q3. 2kg 짜리는 2000G 로 입력하면 되는지

**답: 맞다. 단위는 G / EA 두 개만 둔다.** KG 단위를 만들지 않는다.

### Q4. 검색 필터에 입수량도 넣을지

**답: 넣는다. 네 가지(제품분류 · 중량·수량 · 브랜드 · 입수량).**

### Q5. 같은 조합으로 코드가 또 만들어지는 것을 막을지

**답: 막고 기존 코드를 알려준다.**

### Q6. 여기서 만든 코드를 판매가 계산 화면과 연결할지

**답 (원문):**

> 우선만들기는 하는데 보여지는건 막아줘

→ 연동 기능은 다 넣되 화면 노출은 막아 둔다.
`index.html` 의 `제품코드연동표시` 를 `true` 로 바꾸면 판매가 계산 화면에
「제품코드 불러오기」 드롭다운이 나타난다.

## §6. 후속 요청 (2026-08-27)

> 대분류 생성할때 대분류는 같은데 옵션분류가 여러개 일경우가 있자나
> 그러면 옵션분류에 +,-같은 버튼 생성해서 한번에 생성할수 있게 기능 넣어줘

→ 대분류 생성 폼의 옵션분류를 `+` / `−` 로 늘렸다 줄이는 줄 목록으로 바꾸고,
저장 한 번에 여러 옵션분류를 등록하게 했다.
수정 모드에서는 고르고 있는 한 줄만 다루므로 버튼이 숨거나 비활성이 된다.
목록의 대분류 머리에 `+ 옵션분류` 를 두어, 이미 있는 대분류에 옵션분류만 더 붙일 때
대분류명·코드를 다시 타이핑하지 않게 했다.
