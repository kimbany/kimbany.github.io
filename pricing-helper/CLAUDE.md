# 판매가 설정 도우미

## 이 프로젝트가 다루는 것

**원가를 넣으면 "채널마다 얼마에 팔아야 하는지"를 역산해 주는 계산기.**

판매 채널마다 수수료가 다르고, 채널에 붙은 자사 브랜드마다 포장비가 다르고,
무료배송이면 택배비까지 판매자가 떠안는다. 이 셋을 채널별로 각각 대입해서
목표 마진율이 남는 판매가를 뽑아 준다.

**이 프로젝트가 다루지 않는 것 — 매출 집계, 주문·재고, 정산.**
매출 통합은 `../sales-report/`, 채널별 판매상태는 `../channel-status/` 가 담당한다.
여기는 "판매 전에 가격을 정하는" 단계만 본다.

## 디렉터리

```
pricing-helper/
  CLAUDE.md          이 문서 (설계 결정과 계산 규칙)
  INITIAL_PROMPT.md  최초 요청서 + 확정된 답변 원문
  README.md          사용자용 안내
  index.html         앱 전체 (단일 파일)
```

## 기술 스택

`../sales-report/` · `../channel-status/` 와 같은 구성으로 간다.

- **단일 HTML 파일** — 프레임워크·번들러 없음
- **Tailwind CSS CDN**
- **Firebase Firestore** — 채널 · 브랜드 · 택배 설정값 저장소.
  `index.html` 상단 `파이어베이스설정` 을 채우면 Firestore 모드,
  비워 두면 같은 인터페이스의 `localStorage` 어댑터(로컬 모드)로 동작한다.
  현재 화면 우상단 배지가 어느 모드인지 항상 표시한다.
- **GitHub Pages** 배포 — `https://invedory.com/pricing-helper/`

## 명명 규칙

- **함수명과 주석은 한글로 쓴다.** `판매가역산()`, `백원올림()` 처럼.
- **Firestore 컬렉션·문서 ID 는 ASCII 로 쓴다.** 문서 ID 에 한글이 섞이면 인코딩 사고가 나기 쉽다.
  객체 필드명은 한글을 쓴다(`채널명`, `포장비`).
- **용어는 "제품명" 으로 통일한다. 화면·코드 어디에도 "상품명" 을 쓰지 않는다.**
  (`../sales-report/` 는 "상품명" 을 쓰지만 이 프로젝트는 별개다. 옮겨 오지 말 것.)

## 확정된 계산 규칙

이 6가지는 사용자가 직접 결정한 값이다. **임의로 바꾸지 않는다.**

### 1. 마진율은 판매가 대비다

```
판매가 = (원가 + 포장비 + 택배비) ÷ (1 − 수수료율 − 마진율)
```

마진율 30% = "판매가의 30% 가 마진으로 남는다". 수수료와 같은 기준이라
한 분모에 나란히 들어간다. `수수료율 + 마진율 >= 100%` 면 분모가 0 이하라
계산이 불가능하므로 값을 만들어 내지 말고 카드에 **계산 불가** 로 표시한다.

### 2. 택배비는 "자사 브랜드 › 택배" 에서 관리한다

- 자사 브랜드 대메뉴 아래 중메뉴 2개: **브랜드** / **택배**
- 택배 화면: 추가 · 수정 · 삭제, 항목마다 `택배명` + `택배비(원)`,
  라디오 버튼으로 **기본 택배비** 1개를 지정해 저장
- 판매가 계산 화면의 택배비는 **체크박스가 아니라 드롭다운**이다.
  등록된 택배 항목 중 하나를 골라 계산에 반영하고, "택배비 미포함(구매자 부담)" 도 고를 수 있다.
  화면을 열면 기본 택배비가 미리 선택되어 있다.
- 포장비는 브랜드에, 택배비는 택배 항목에 있다. 둘을 한곳에 합치지 않는다.

### 3. 원가는 판매 1건 기준, 입수량은 표시용

입력한 원가 = 실제로 팔 1건(1세트)의 원가다. 입수량(n개~n개)은 제품 정보로
결과 카드에 함께 적기만 하고 **나눗셈에 쓰지 않는다.**
단위 환산은 "원가 계산" 화면에서 이미 끝내고 넘어오므로, 여기서 또 나누면 이중 나눗셈이 된다.

### 4. 모든 금액은 VAT 포함이다

원가 · 포장비 · 택배비 · 결과 판매가 전부 VAT 포함 금액으로 통일한다.
별도 환산 로직을 두지 않는다.

**금액·퍼센트를 입력받는 모든 칸과 계산 결과를 보여주는 모든 곳에
"VAT 포함" 안내 문구를 붙인다.** (`VAT배지()` 헬퍼를 쓴다.)

### 5. 끝자리 — 100원 올림이 기본, 800원가는 보조 표기

- **대표 판매가 = 100원 단위 올림.** 12,340원 → 12,400원.
  항상 올림이라 목표 마진율을 밑돌지 않는다.
- **그 아래 작게 800원으로 끝나는 가격도 함께 보여준다.** 규칙은 "올림":
  13,450원 → 13,800원 (12,800원 아님), 14,110원 → 14,800원 (13,800원 아님).

  ```
  천단위 = floor(금액 / 1000) × 1000
  후보  = 천단위 + 800
  후보 < 금액 이면 후보 += 1000
  ```

- 두 가격 모두 **반올림 후 실제 마진율을 다시 계산해서** 함께 표시한다.
  올림한 판매가로 수수료를 다시 곱해야 실제로 남는 돈이 나온다.

## 데이터 구조

설정값은 몇 건 수준이라 **종류별 문서 1개에 배열로 담는다.** 읽기 3회로 전체 로드가 끝난다.

```
pricing_helper/channels
  목록  [ { id, 채널명, 수수료율, 브랜드ID, 정렬 } ]

pricing_helper/brands
  목록  [ { id, 브랜드명, 포장비 } ]

pricing_helper/shipping
  목록  [ { id, 택배명, 택배비 } ]
  기본택배ID  "s..."          ← 라디오로 고른 기본 택배비 1개
```

- `수수료율` 은 **0~1 실수가 아니라 퍼센트 숫자 그대로** 저장한다(10.5 = 10.5%).
  화면 입력값과 저장값이 같아야 사람이 Firestore 콘솔에서 봐도 헷갈리지 않는다.
  계산 직전 `퍼센트→비율()` 로 나눈다.
- `채널.브랜드ID` 가 가리키는 브랜드가 지워지면 포장비 0 으로 계산하고
  카드에 **브랜드 연결 끊김** 을 표시한다. 조용히 0 으로 넘기지 않는다.

## 화면 구성

```
판매가            (대메뉴)
  ├ 원가 계산     입고 단위 → 판매 단위 환산 원가. "판매가 계산으로 보내기" 로 값 전달
  └ 판매가 계산   원가 → 채널별 판매가 역산. 결과는 채널별 영수증 카드
채널 기본설정      (대메뉴, 중메뉴 없음) 채널명 · 수수료% · 연결 브랜드 CRUD
자사 브랜드        (대메뉴)
  ├ 브랜드        브랜드명 · 포장비 CRUD
  └ 택배          택배명 · 택배비 CRUD + 기본 택배비 라디오 선택
```

### 결과 카드 규칙

- **채널 1개 = 카드 1개.** 영수증처럼 항목이 세로로 쌓인다.
- 마진율 입력칸이 여러 개면 **한 카드 안에서 마진율별로 구분**해 각각 보여준다.
  마진율마다 카드를 새로 만들지 않는다(채널 비교가 목적이므로 채널이 바깥 축이다).
- 각 마진율 블록에 **원가 · 포장비 · 택배비 · 수수료 · 마진 · 최종 판매가**를 모두 적는다.
  하나라도 0 원이면 생략하지 말고 `0원` 으로 적는다. 빠진 항목은 계산 착오로 읽힌다.
