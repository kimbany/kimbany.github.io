## 0. 세 단계 한눈에 보기

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                              │

│   인용                각 모달 인코딩          호흡 안무로 렌더                │
│   공간                매니폴드 투영          최소 30초 게이트                │
│   느낌                Claude 합성                                            │
│                                                                              │
│   1–3분               12–60초 (게이트)       1–2분 (스크롤)                  │
```

세 단계의 핵심 규칙:

- **단계 사이는 직선이 아니라 호흡.** 각 경계에 의도된 정적 비트가 있습니다.
- **각 단계는 자신의 실패에 대해 정직.** 다음으로 거짓을 전달하지 않습니다.
- **타이밍은 컴퓨팅이 아니라 경험에 의해 결정됨.** 모델이 일찍 끝나도 게이트를 유지합니다.

## 1. Stage 1 — 사용자 업로드

다섯 가지 헌물의 수집. 사용자가 자신의 증거를 시스템에 *건네는* 단계.

### 1.1 다섯 헌물의 사양

| 모달 | 형식 | 수량 | 입력 방식 |
|---|---|---|---|
| **이미지** | JPEG · PNG · WebP · HEIC | 9–24장 | 드래그·드롭, 파일 선택, 붙여넣기 |
| **소리** | MP3 · WAV · FLAC · 스트리밍 링크 | 3–10곡 | 파일 업로드, Spotify/Apple Music/SoundCloud URL |
| **인용** | UTF-8 텍스트 | 3–7개 | 직접 타이핑, 클립보드 붙여넣기 |
| **공간** | 큐레이션된 9장 중 선택 | 3–9개 | 시스템 제공 사진에서 탭 선택 |
| **느낌** | 5개의 0.0–1.0 부동소수점 + 망설임 시간 | 5개 고정 | 슬라이더 |

### 1.2 수집 파이프라인


### 1.3 Evidence 데이터 모델

```ts
type Evidence = {
  id: string;                    // ulid
  userId: string;
  kind: 'image' | 'sound' | 'quote' | 'space' | 'feeling';

  // 저장 위치 (kind에 따라 일부만)
  storageKey?: string;           // S3 키 (이미지/오디오)
  text?: string;                 // 인용 본문
  spaceId?: string;              // 공간 큐레이션 ID
  feelingAxis?: number;          // 1–5 (느낌 슬라이더 번호)
  feelingValue?: number;         // 0.000–1.000
  feelingHesitationMs?: number;  // 머문 시간

  // 메타데이터
  perceptualHash?: string;
  createdAt: Date;
  source: 'onboarding' | 'tend' | 'import';

  // 가공된 사본
  normalizedKey?: string;
  thumbnailKey?: string;
};
```

### 1.4 업로드 단계의 UX 약속

- **속도가 아니라 정확함을 보여줍니다.** 진행률 바 대신, 업로드된 항목이 즉시 적절한 위치에 *착지* — 그 시각이 진행 자체.
- **실패는 자리에서 회복.** 한 항목이 실패하면 그 자리에서 다시 시도 어포던스, 전체 흐름이 멈추지 않음.
- **9장 도달 시 한 줄.** *"시작하기엔 충분해요. 더 두어도 좋고요."* — 사용자에게 다음을 강요하지 않음.
- **건너뛰기는 수치심 없이.** "오늘은 아니에요" 링크는 모든 헌물에 존재. 부재도 증거.

### 1.5 단계 종료 조건

다섯 모달 중 **최소 3개**에서 최소 임계 수량을 충족해야 다음 단계로:

- 이미지 ≥ 9 또는
- 소리 ≥ 3 또는
- 인용 ≥ 3 또는
- 공간 ≥ 3 또는
- 느낌 = 5 (전부 필수, 슬라이더 5개는 묶음)

3개 미만이면 분석은 시작되지만 *부분 모드*로 진입 — 시스템은 명시적으로 *"여기까지 보여요. 아직 함께 걷지 않은 방들이 있어요."*

## 2. Stage 2 — AI 취향 분석

증거를 벡터로, 벡터를 흐름으로, 흐름을 의미로 변환. 모델이 *듣는* 단계.

### 2.1 분석의 여섯 하위 단계

```
[2.1] 인코딩          → 각 모달을 임베딩으로
[2.2] 매니폴드 투영    → 64-d 통합 공간으로 사상
[2.3] 클러스터링      → UMAP + HDBSCAN으로 흐름 추출
[2.4] 패턴 탐지       → 모달 간 일관성·역류·침묵
[2.5] 정렬           → 12 철학 사조와의 친족 점수
[2.6] 서사 합성       → Claude로 이름·산문·미러 문장
```

각 단계는 다음에 명확한 계약을 전달합니다. 단계는 캐시 가능, 멱등, 재실행 가능.

### 2.2 인코딩 사양

| 모달 | 인코더 | 출력 차원 | 보조 피처 |
|---|---|---|---|
| 이미지 | OpenCLIP `ViT-L/14` + 미적 헤드 | 768 | — |
| 공간 | 같은 인코더 + 공간 분류기 | 768 + 8 | 내/외부, 광원 방향, 천장 높이, 재료 |
| 오디오 | CLAP `HTSAT-base` | 512 | BPM, 키, 화성 안정성, 다이내믹 레인지, 침묵 비율 |
| 인용 | sentence-transformer `bge-m3` | 1024 | 가치, 추상도, 시제 분포, 대명사 분포 |
| 느낌 | 직접 사용 (피처 엔지니어링 없음) | 5 + 5 | 슬라이더 값, 망설임 시간 |

**모든 임베딩은 L2 정규화.** 보조 피처는 robust scaler로 [0, 1]에 사상한 뒤 학습된 가중치로 결합.

### 2.3 매니폴드 투영

연결된 raw 임베딩 (~2300-d)을 학습된 선형 헤드로 **64-d Taste Manifold**에 투영. 헤드는 큐레이션된 사용자 표본으로 사전 학습, v1에서는 동결.

```
TasteVector = LinearHead( concat(
  image_emb,         // 768
  space_emb,         // 768 + 8
  audio_emb,         // 512 + 9
  quote_emb,         // 1024 + 6
  feeling_emb        // 10
)) → 64-d
```

투영된 벡터는 즉시 세 슬라이스로 분할:

- **L1 / Impression** — 44-d, 빠른 변동, 주별
- **L2 / Atmosphere** — 14-d, 중간 변동, 계절별
- **L3 / Constitution** — 6-d, 느린 변동, 연 단위

각 축마다 **확신 점수** (증거 밀도 × 모달 간 일치도)를 함께 계산하여 저장.

### 2.4 클러스터링 — 흐름 추출

```
TasteVector + 개별 evidence 벡터
        │
        ▼
┌─────────────────────────────────┐
│  UMAP                            │
│  n_neighbors = 15                │
│  min_dist = 0.1                  │
│  metric = 'cosine'               │
│  n_components = 2 (시각화 캐시) │
└─────────────────┬────────────────┘
                  │
                  ▼
┌─────────────────────────────────┐
│  HDBSCAN                         │
│  min_cluster_size = 2            │
│  cluster_selection_method = leaf │
│  metric = 'euclidean' on UMAP    │
└─────────────────┬────────────────┘
                  │
                  ▼
┌─────────────────────────────────┐
│  테마 병합                        │
│  코사인 유사도 ≥ 0.78 → 같은 흐름 │
│  결과: 4–7개 미세 클러스터        │
│  추가 병합 → 2–4개 흐름          │
└─────────────────────────────────┘
```

**`min_cluster_size = 2`는 의도된 작음.** 24장 중 단일 이상 이미지는 *신호*입니다 — 잡음이 아니라 가장 드러내는 증거일 수 있습니다.

### 2.5 패턴 탐지

다음 일곱 패턴을 병렬로 검사:

| 패턴 | 시그니처 |
|---|---|
| Counter-Current (역류) | 두 모달 간 코사인 ≤ 0.2 |
| Hour (시간) | 광원 방향 + 템포 + 시제가 좁게 군집 (분산 ≤ 0.15) |
| Reach (닿음) | 인용 추상도 ≥ 0.7 ∧ 이미지 구체성 ≥ 0.7 |
| Refuge (은신처) | 이미지 80%가 단일 광원·실내 |
| Horizon (지평) | 가장자리·거리·외부·미래형 빈도 합 ≥ 0.6 |
| Echo (메아리) | 3개 이상 evidence에 반복 어휘·시각 모티프 |
| **Silence (침묵)** | *부재한* 축 — 사람 없음, 원색 없음, 빠른 템포 없음 |

각 패턴이 임계값을 통과하면 `EmotionalPattern` 객체로 기록, **`strength × novelty` 점수**로 정렬. 보고서는 상위 **2–4개**만 사용 (그 이상은 관찰이 아니라 뷔페가 됨).

### 2.6 철학적 정렬

12 사조의 프로토타입 벡터와 사용자 L2 벡터 간 코사인 유사도 계산. 각 사조에 대해:

```ts
type PhilosophicalResonance = {
  school: SchoolId;
  kinship: number;        // 0–1, 코사인 유사도
  agreeing_axes: AxisId[]; // 사용자와 사조가 일치하는 축들
  disagreeing_axes: AxisId[]; // 사용자가 사조에서 벗어나는 축들
  prose: string;          // 마찰을 명시적으로 포함한 한 단락
};
```

상위 **2–3개** 사조와 그 마찰점을 유지. **할당이 아닌 정렬** — "당신은 도가입니다"는 결코 없음, "당신의 세 흐름이 도가 미학과 함께 흐릅니다 — 그러나 템포는 더 빠릅니다, 그 빠른 맥박은 당신의 것입니다"가 있을 뿐.

### 2.7 서사 합성 (Claude 호출)

두 개의 병렬 Claude 호출:

**Call A — 흐름 이름 짓기**
```
입력:   각 흐름의 상위 6축 (극 이름), 우세 팔레트, 대표 증거 3개
출력:   각 흐름의 두 단어 명사구 (후보 8개 → 차단 목록 필터 → 1개 선택)
모델:   claude-opus-4-7
온도:   0.8
```

**Call B — 시네마틱 보고서 + 미러 문장**
```
입력:   L2 벡터, 상위 축, 명명된 흐름, 우세 팔레트, 우세 시간,
        철학적 공명, 역류 관찰 3개, 구체적 증거 4조각
출력:   250–400 단어 4막 산문 + 한 문장 미러
모델:   claude-opus-4-7
온도:   0.7 (보고서), 0.6 (미러)
```

**미러 문장의 제약 (시스템 프롬프트):**
- 정확히 한 문장.
- 2인칭.
- 구체-그다음-추상, 또는 그 역.
- "당신은 …같아요" 비유 금지.
- 정신적으로 *반증 가능*해야 함 — 틀릴 수도 있는 무언가를 말해야 함.

### 2.8 결과 봉인

모든 출력은 `(user_id, evidence_hash, model_version, prompt_hash)`로 캐시 키 부여. 같은 증거로 다시 호출하면 무료 — Claude 비용 없음. 증거가 하나 추가되면 임베딩 단계만 그 항목에 실행, 클러스터링부터 점진적으로 재실행.

## 3. Stage 3 — Cinematic Taste Report 생성

분석이 끝났습니다. 사용자에게 *건네는* 단계. 이 단계의 모든 동작은 디자인 시스템의 **호흡(Breath)** 언어로 안무됩니다.

### 3.1 표면화의 다섯 비트

```
[3.1] 문턱 비트         → 풀스크린 호흡 ("잠시 머물러 주세요")
[3.2] 별자리 형성        → WebGL 라이브 비주얼 (25–40초)
[3.3] 듣기 카피           → 세 문장이 순차 등장
[3.4] 게이트 통과         → "─ 열기 ─" 단일 버튼
[3.5] 드러남             → Genome 카드 긴 스크롤 + 미러 카드
```

### 3.2 문턱 비트

```
ON entry:
  - 현재 화면이 1.4초 날숨으로 void에 사라짐
  - 검은 필드, 한 문장 페이드인 (reveal blur, 1.6초)
    "잠시 머물러 주세요."
  - 2.5초 정지
  - 다음 비트로 전환
```

이 비트는 *건너뛸 수 없습니다*. 시간이 마법의 일부입니다.

### 3.3 별자리 형성

R3F (`react-three-fiber`) 캔버스가 풀스크린으로 떠오릅니다.

```
점 구름 초기 상태:
  - 5개 클러스터 (각 모달)
  - 각 evidence는 한 점
  - 위치: 균일 분포 + 약한 인력 (모달 내)
  - 색: pearl, alpha 0.4–0.7

진행:
  t = 0–8초     모달 내 클러스터링 (Verlet 시뮬레이션)
  t = 8–16초    모달 간 가교선 등장 (엣지 가중치 ≥ 0.6)
  t = 16–28초   흐름이 형성, 색이 미세하게 따뜻해짐
  t = 28–40초   회전 4° + 호버 가능 상태로 안정

성능:
  - 노드 ≤ 200개로 캡 (evidence가 많아도)
  - 60fps 목표, M 시리즈
  - 저사양: 2D Canvas + 단순 force-directed 폴백
```

### 3.4 듣기 카피

별자리 위에 세 문장이 8초씩 머뭅니다 (총 24초):

```
1. "당신의 이미지 속 빛을 읽고 있어요…"
2. "당신 소리의 온도를 듣고 있어요…"
3. "관통하는 선을 찾고 있어요."
```

각 문장은 reveal blur로 진입 (`blur(14px) → blur(0)`, 1.6초), 자간 `+0.12em → +0.03em`.

**모델이 일찍 끝나도 24초는 유지.** 모델이 늦으면 *"여전히 듣고 있어요…"* 추가 문장으로 게이트 연장 (최대 60초).

### 3.5 게이트 통과

별자리가 안정되고 듣기 카피가 끝나면, 화면 하단 중앙에:

```
─ 열기 ─
```

`Beacon` (ceremonial use) — 헤어라인 보더, 양옆 대시, 0.6Hz 펄스. 사용자가 탭할 때까지 시스템은 기다립니다. *문턱은 사용자가 넘는 것이지 시스템이 미는 것이 아닙니다.*

### 3.6 드러남 — Genome 카드

탭과 동시에:
1. 별자리가 1.4초 날숨으로 사라짐.
2. 검은 필드, 0.6초 정적.
3. `Taste Name`이 reveal blur로 진입 (1.6초, 120px display serif).

그 아래로 긴 스크롤 카드, 박물관 명패처럼:

```
1. 취향 이름            (display xl)
2. 시네마틱 산문         (250–400 단어, text-lg, 4막)
3. 흐름                  (2–4개, 강도·안정성 주석)
4. 분위기                (8개 프로파일링)
5. 여섯 축                (극 이름 + 희미한 막대)
6. 팔레트                (5색 스와치, 명명)
7. 친족                  (6명: 예술가, 감독, 건축가, 작곡가, 작가, 와일드카드)
8. 공명                  (2–3 철학 사조, 마찰 포함)
9. 미러 줄              (이탤릭, 자신의 카드 위에 홀로)
```

### 3.7 미러 카드

Genome 카드 마지막에 도달하면, 페이지가 자연스럽게 검은 필드로 전환:

```
─────────────────────────────────────────────────────

       당신은 아름다움을 모으는 게 아니에요 — 한때
       세상이 누군가에게 다정했다는 증거를 모으는
       거예요.

       ─ 간직하기 ─

─────────────────────────────────────────────────────
```

display md (52px) 이탤릭, 중앙, 1.6초 reveal blur로 진입.

`간직하기` 버튼은 미러 문장을 `MirrorRecord`로 봉인 — 사용자의 L3 헌법 층에 기준점으로 등록. 미래에 시스템이 사용자에 대해 말할 모든 것은 이 문장과 정합해야 합니다.

### 3.8 입장 — Field로의 전환

미러를 간직하면, 마지막 비트:

```
화면이 검은 필드 → 따뜻한 빛의 긴 세로 사각형 ("문")
                  → 패럴랙스로 열림 (커서 따라)
                  → Field 표면이 inhale로 드러남

카피:  "들어오세요. OS는 당신 같은 사람을 기다리고 있었어요."
```

여기서 온보딩이 끝나고 Field가 시작됩니다 — 같은 OS 안의 다른 방으로.

각 단계가 다음에게 무엇을 건네는지의 명확한 명세.

### 4.1 Stage 1 → Stage 2

```ts
type OnboardingSubmission = {
  userId: string;
  sessionId: string;

```

### 4.2 Stage 2 → Stage 3

```ts
type GenomeArtifact = {
  userId: string;

  // 정량
  vector: {
    impression: Float32Array;    // 44
    atmosphere: Float32Array;    // 14
    constitution: Float32Array;  // 6

  };

  // 정성
  currents: Current[];           // 2–4
  patterns: EmotionalPattern[];  // 2–4
  resonances: PhilosophicalResonance[]; // 2–3

  // 분위기
  atmosphere: {
    hour: { from: string; to: string };
    climate: string;
    materials: string[];
    light: { sources: number; direction: string; kelvin: number };
    soundFloor: { min: number; max: number; unit: 'dB' };
    pace: string;
    scale: string;
    weather?: string;
  };
  palette: { hex: string; name: string }[]; // 5

  // 친족
  kin: { name: string; discipline: string }[]; // 6

  // 서사
  tasteName: string;             // "Lacquered Dusk"
  portrait: string;              // 250–400 단어 4막

  modelVersion: string;
  computedAt: Date;

```

```ts
type GenomeRecord = GenomeArtifact & {
```

## 5. 지연 안무 (Latency Choreography)

**시간은 컴퓨팅이 아니라 경험이 결정합니다.**

### 5.1 단계별 예산

| 단계 | 컴퓨팅 시간 | 경험 시간 | 차이를 어떻게 채우는가 |
|---|---|---|---|
| 1.1–1.5 업로드 | 1–3초 | 사용자 페이스 | 즉시 옵티미스틱 미리보기 |
| 2.1 인코딩 | 4–8초 | (백그라운드) | 사용자가 다음 헌물을 채우는 동안 시작 |
| 2.2 투영 | <100ms | — | — |
| 2.3 클러스터링 | 1–2초 | — | — |
| 2.4 패턴 | <500ms | — | — |
| 2.5 정렬 | <100ms | — | — |
| 2.6 합성 | 12–20초 | 최소 24초 | 듣기 카피 3문장 |
| 3.1 문턱 | — | 4.2초 (호흡 + 정적) | 호흡 그 자체 |
| 3.2–3.4 별자리 | — | 25–40초 | 별자리 시각화 |
| 3.5 게이트 | — | 사용자 페이스 | 사용자가 탭할 때까지 대기 |
| 3.6 드러남 | — | 1–2분 (스크롤) | 사용자 페이스 |

**총: 약 8–11분** — 짧은 영화의 길이.

### 5.2 게이트 규칙

- 문턱 비트 4.2초 — *고정*.
- 별자리 + 듣기 24초 — *최소*. 모델이 24초 후 끝나면 즉시 게이트 통과 가능.
- 모델이 24초 안에 끝나면 추가 12초 보너스 안무 (별자리 회전 + 정적).
- 모델이 60초 초과하면 *"여전히 듣고 있어요…"* 문장 등장, 사용자는 떠나거나 계속 머무를 수 있음 (앱은 IndexedDB에 진행 상태 보존).

### 5.3 백그라운드 워밍

사용자가 Stage 1의 4번째 헌물(공간)에 도달하면, 시스템은 *이미 인코딩을 시작합니다*. 5번째 헌물(느낌)이 끝날 때쯤에는 임베딩이 거의 준비되어 있어, Stage 2의 가장 무거운 부분은 사용자가 다음 화면으로 넘어가는 동안 끝납니다. 이것이 24초 안에 합성이 끝나는 이유입니다.

## 6. 실패 처리

### 6.1 실패는 결코 에러로 표시되지 않음

빨간색 없음, 느낌표 없음, "오류 발생" 없음. 모든 실패는 *문장*이 됩니다.

| 실제 실패 | 사용자에게 보이는 것 |
|---|---|
| 업로드 네트워크 끊김 | 항목 옆 작은 회색 점, *"다시 시도해 보세요"* whisper link |
| 임베딩 GPU 만석 | 듣기 카피가 *"여전히 듣고 있어요…"*로 전환 |
| Claude API 5xx | 게이트가 *"우리에게 한 순간 더 필요해요. 머물 수 있다면 머물러 주세요."*로 머묾 |
| 부분 실패 (예: 오디오만) | 분석은 진행, *"당신의 소리는 다음에 들어볼게요"* 가 Genome에 명시됨 |
| 모델 출력이 가드레일 위반 | 자동 재합성, 사용자에게는 그저 평소보다 약간 긴 듣기로 보임 |

### 6.2 부분 모드의 정직함

3개 미만 모달이 채워졌을 때:
- Genome 카드는 더 짧게 — *"여기까지 보여요."*
- 확신 리본은 가시적으로 옅음.
- 미러 문장은 생성하되, 그 끝에 *"아직 함께 걷지 않은 방들이 있어요. 준비되면 돌아와 주세요."*

**시스템은 결코 허구를 만들지 않습니다.** 추측보다 침묵이 낫습니다.

### 6.3 재실행 / 진화

사용자가 헌물을 추가하거나 Atmosphere에서 Tend할 때마다:
- 새 evidence만 임베딩.
- 클러스터링·패턴·정렬을 점진적으로 재계산.
- L1 / Impression은 매일 갱신.
- L2 / Atmosphere는 매주 갱신.
- L3 / Constitution은 벡터 델타 > 0.15 코사인일 때만 (보통 4–9개월).
- 미러 문장은 L3가 바뀐 후에만 새로 생성. 그리고 사용자에게 조용한 이메일: *"당신 안의 무언가가 천천히 돌아섰어요. 준비되면 보러 오세요."*

## 7. 닫는 말

세 단계 — 업로드, 분석, 리포트 — 는 기술적으로 자명합니다. 어렵게 만드는 것은 그 사이의 *호흡*입니다. 단계 사이의 30초 게이트. 듣기 카피의 3문장. 문턱 비트의 4.2초. 별자리의 회전. 미러 문장의 1.6초 reveal blur.

엔지니어가 이 문서를 읽고 "왜 이렇게 느리지?"라고 묻는다면, 답은: 빠른 것이 더 쉽지만 빠른 것은 이 제품이 아닙니다. *기다림이 곧 마법입니다.* 시스템이 사용자에 대해 신중히 생각한다고 느끼게 만드는 것이 시스템이 사용자에 대해 신중히 생각하게 만드는 것보다 중요합니다 — 우리는 둘 다 합니다, 하지만 *순서*는 신중함을 *느끼게* 하는 것이 먼저입니다.

세 동작. 그 사이의 호흡. 이것이 Taste OS의 전부입니다.
