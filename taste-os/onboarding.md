# Taste OS — 온보딩 구현 명세

> 이건 가입 양식이 아니에요. 처음 들어오는 사람과, 그 사람이 자기 자신을 만나는 7분짜리 짧은 영화입니다.

이 문서는 Taste OS 온보딩의 **구현 사양**입니다. 디자인 철학과 12막 흐름은 `README.md` / `README.ko.md`에 이미 정의되어 있어요. 이 문서는 그것을 **7개의 화면**으로 압축해 실제 페이지로 만들기 위한 가이드입니다.

함께 읽기: `README.md` (12막 원본), `voice.md` (한국어 보이스), `system.md` (디자인 시스템), `landing-v2.md` (랜딩 v2의 톤·팔레트).

구현: `taste-os/onboarding/index.html` + `style.css` + `script.js`. 머지 후 `kimbany.github.io/taste-os/onboarding/`에서 볼 수 있어요.

## 0. 철학 — 양식이 아니라 자리

대부분의 온보딩은 **양식**이에요. 다음 단계로 가기 위해 채워 넣어야 하는 빈칸. Taste OS의 온보딩은 **자리**입니다. 잠시 머무는 곳, 그동안 시스템이 사용자가 보여준 것들을 천천히 받아들이는 곳.

### 다섯 가지 약속

1. **서두르게 만들지 않습니다.** 진행 바도, 카운트다운도, "1분 후 시작" 같은 압박도 없어요.
2. **건너뛰는 것을 부끄럽지 않게 합니다.** 모든 화면에 *"오늘은 아니에요"* 가 작게 있고, 그래도 분석은 시작돼요. 그저 더 적게 들어볼 뿐이에요.
3. **선택은 깊어지는 것이지 체크되는 것이 아닙니다.** 선택된 카드는 체크 표시가 아니라 *채도가 깊어지는* 방식으로 응답해요.
4. **빠른 입력 후엔 600ms 멈춤.** 시스템이 *받아들이는 시간* 을 시각적으로 보여줍니다.
5. **마지막 비트는 게이트로 잠겨 있습니다.** 모델이 빨리 끝나도 듣기 화면은 최소 24초 머무릅니다. 기다림이 곧 마법이에요.

### 절대 없는 것

- 진행 바 (`%` 형태)
- "X개 더 선택해주세요" 같은 강제 카운터
- "다음" 버튼 (대신 Beacon이 적절한 순간에 등장)
- 토스트, 모달, 도움말 툴팁
- "거의 다 왔어요!" 같은 격려 메시지
- 어떤 형태의 이모지

## 1. 화면 흐름 & 상태 아키텍처

7개의 화면이 단일 페이지 안에서 상태로 전환됩니다 (Next.js로 구현 시에는 라우트로 분리하되 같은 레이아웃 안에서 cross-fade).

```
                                                                
  Screen 1     Screen 2    Screen 3    Screen 4    Screen 5    Screen 6    Screen 7
  ────────     ────────    ────────    ────────    ────────    ────────    ────────
  도착   →    이미지  →    소리   →    말     →    공간   →    느낌    →    듣기
  (intro)     (~6장)      (~3장)      (~3개)      (~3장)      (5축)       (24s 게이트)
                                                                
       각 전환:  현재 화면 1.4s 날숨  →  검은 필드 600ms  →  다음 화면 1.0s 들숨
```

### 상태 모델

```ts
type OnboardingState = {
  step: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  selectedImages: Set<number>;     // 16개 중 선택
  selectedMusic: Set<number>;       // 9개 중 선택
  selectedQuotes: Set<number>;     // 9개 중 선택
  customQuote: string | null;
  selectedSpaces: Set<number>;     // 9개 중 선택
  feeling: number[];                // 5개 슬라이더, 0.0–1.0
  feelingStep: 0 | 1 | 2 | 3 | 4;  // 현재 슬라이더 인덱스
};
```

상태는 메모리에만 보관됩니다. 새로고침하면 처음부터. 실제 제품에서는 `idb-keyval`로 IndexedDB에 자동 저장돼요 (`pipeline.ko.md` §1.2 참고).

### 임계값 — 진행 가능 조건

| 화면 | 다음으로 가려면 |
|---|---|
| 도착 | 항상 가능 |
| 이미지 | ≥ 6장 선택 (또는 "오늘은 아니에요") |
| 소리 | ≥ 3개 (또는 건너뛰기) |
| 말 | ≥ 2개 또는 직접 작성 (또는 건너뛰기) |
| 공간 | ≥ 3개 (또는 건너뛰기) |
| 느낌 | 5개 슬라이더 모두 적어도 한 번 만짐 |
| 듣기 | 최소 24초 경과 + 사용자 탭 |

3개 모달 미만이 채워지면 시스템은 *"여기까지 보여요. 함께 걷지 않은 방들이 있어요"* 메시지를 표시합니다.

## 2. Screen 1 — 도착

**목적.** 양식의 첫 칸이 아니라, 영화의 첫 컷처럼 시작합니다.

### 구성

```
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                       괜히 자꾸                                
                  저장하게 되는 것들이                          
                          있어요.                               
                                                                
                                                                
                  ─ 그 작은 것들이 사실 ─                       
                  ─  당신을 가장 잘 말해요. ─                   
                                                                
                                                                
                                                                
                                                                
                       ─ 들어가기 ─                             
                                                                
                                                                
```

### 시퀀스

```
t = 0.0s    검은 필드, Sigil + 호흡하는 작은 점
t = 1.2s    첫 문장 reveal blur (1.8s)
t = 4.0s    첫 문장이 자리잡음, 잠시 멈춤
t = 5.6s    두 번째 문장 (mist 색, 작게) reveal
t = 8.4s    Beacon 등장
```

### 카피

| 슬롯 | 한국어 |
|---|---|
| 메인 | 괜히 자꾸<br/>저장하게 되는 것들이<br/>있어요. |
| 서브 | 그 작은 것들이 사실<br/>당신을 가장 잘 말해요. |
| Beacon | ─ 들어가기 ─ |

영어 보조: *"There are things you keep returning to. Those small things tell us who you are."*

## 7. Screen 6 — 느낌

**목적.** 5개의 시적 양극 슬라이더. 한 화면 안에서 한 번에 하나씩 진행됩니다.

### 화면 구성

```
                                                                
                                                                
                                                                
   정답은 없어요. 마음이 가는 쪽으로, 천천히.                  
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
        고독                                       교감          
                                                                
              ────────────●────────────                          
                                                                
                                                                
                                                                
                                                                
                                                                
                                                                
                          1 / 5                                  
                                                                
                                                                
```

### 5개 슬라이더

순서대로 표시 (한 번에 하나):

1. 고독 ↔ 교감
2. 와비사비 ↔ 순결한 기하
3. 기억 ↔ 기대
4. 침묵 ↔ 울림
5. 흙 ↔ 대기

### 상호작용

- 슬라이더 트랙은 헤어라인 + 빛나는 점 하나
- 사용자가 드래그하면 점이 따라감
- 점을 놓으면 다음 슬라이더로 자동 전환 (페이드)
- 망설임 시간 (드래그 시작에서 놓을 때까지) 도 기록 — 실제 제품에서는 신호로 사용

### 카피

| 슬롯 | 한국어 |
|---|---|
| 헤더 | 정답은 없어요. 마음이 가는 쪽으로, 천천히. |
| 진행 표시 | 1 / 5, 2 / 5, … |
| 다섯 번째 완료 후 자동 전환 | (사용자 입력 없이 다음 화면으로) |

## 8. Screen 7 — 듣기

**목적.** AI 분석을 시각화하는 **시네마틱 듣기 비트**. 최소 24초 유지.

### 구성

```
                                                                
                                                                
                          ·         ·                            
                       ·  ·  ·  ·                                
                    ·   · · ·  · ·                               
                   ·  · ╳ · ·  · ·                               
                    ·   · · · · ·                                
                       ·  ·  ·                                   
                          ·                                      
                                                                
                                                                
            당신이 보여준 빛을 읽는 중이에요…                   
                                                                
                                                                
                                                                
```

### 별자리 애니메이션

- 약 36개의 점이 화면 중앙 영역에 흩어져 있음
- 처음에는 각자 자리에 정적으로
- 8초 후: 점들이 미세하게 클러스터링 (Verlet 시뮬레이션 간소화 — `transform`만 변경)
- 16초 후: 가는 선들이 점 사이에 그려짐 (`stroke-dasharray` 애니메이션)
- 24초 후: 별자리가 안정됨, 4°의 매우 느린 회전

### 세 문장 시퀀스

```
t =  0–8s   "당신이 보여준 빛을 읽는 중이에요…"     (reveal blur 1.6s, 6.4s 유지, 1.4s 날숨)
t =  8–16s  "당신 안의 온도를 듣는 중이에요…"
t = 16–24s  "관통하는 선을 찾고 있어요."
t = 24s+    Beacon 등장: ─ 열기 ─
```

### Beacon 클릭 후 (미리보기 종료 상태)

별자리가 1.4초 날숨 → 검은 필드 → 한 문장:

> *지금까지가 미리보기였어요.*
> *당신의 풍경은 실제 Taste OS에서 만들어집니다.*
>
> ─ 처음으로 ─

이 미리보기 페이지는 실제 Genome을 생성하지 않습니다. 그건 백엔드 모델이 필요하니까요. 미리보기는 *경험의 안무* 만 보여줍니다.

## 9. 모션 & 전환

### 화면 간 전환

```
                                                                  
   현재 화면          검은 필드          다음 화면              
  ────────         ────────         ────────                   
  날숨 1.4s    →    멈춤 0.6s    →    들숨 1.0s                  
                                                                  
       cubic-bezier:                cubic-bezier:                
       0.70, 0, 0.84, 0             0.16, 1, 0.30, 1             
                                                                  
   총 전환 시간: 3.0초                                            
                                                                  
```

이 3초의 검은 정적이 *시스템이 받아들이는 시간* 입니다. 사용자가 방금 한 선택을 시스템이 *고려하고 있다* 는 느낌을 주는 디자인 결정이에요.

### 내부 모션 (한 화면 안에서)

- **카드 선택 시:** 채도 +6%, inner glow 1px (200ms)
- **카드 hover:** 2px 위로 (160ms)
- **Beacon 활성화:** 헤어라인 보더가 mist에서 ember로 (400ms), 0.6Hz 펄스 시작
- **헤더 등장:** reveal blur 1.6s
- **카운터 업데이트:** 숫자가 fade-cross로 교체 (300ms)

### 별자리 (Screen 7) 특수 모션

- 36개 점이 절대 위치로 배치되어 처음엔 정적
- 8초 후: 각 점이 자신의 클러스터 중심 방향으로 ±12px translate (4s easing)
- 16초 후: SVG `<line>` 요소들이 등장, `stroke-dasharray`로 그려짐
- 24초 후: 전체 컨테이너에 `transform: rotate(4deg)` (12s linear → 정지)

## 10. 인터랙션 원칙

`system.md`의 6대 원칙을 그대로 따릅니다. 온보딩 특수 원칙:

1. **선택은 즉시 응답.** 200ms 내 시각 피드백.
2. **선택은 취소 가능.** 다시 탭하면 풀려요. *"정말 취소하시겠어요?"* 다이얼로그 없음.
3. **카운트는 부드럽게.** *"3장 골랐어요"* 가 *"3 / 12"* 보다 낫습니다. 목표를 강제하지 않아요.
4. **Beacon은 임계값에 도달하면 등장.** 임계값 미달 시 Beacon은 보이지 않음 (재촉 메시지 대신).
5. **"오늘은 아니에요" 는 부끄럽지 않게.** 화면 우하단, mist 색, 작게. 클릭 시 다음 화면으로 그대로 진행.

### 상태 전환 핵심 코드 (스케치)

```js
async function goToScreen(n) {
  const current = document.querySelector('.screen.is-active');
  const next = document.querySelector(`.screen[data-step="${n}"]`);
  if (!next || next === current) return;

  // 1. exhale
  current.classList.remove('is-active');
  current.classList.add('is-exiting');
  await wait(1400);

  // 2. void pause
  current.classList.remove('is-exiting');
  await wait(600);

  // 3. inhale
  next.classList.add('is-active');
  // CSS handles the 1.0s breath-in
}
```

## 닫는 말

대부분의 온보딩은 *완료* 를 위해 설계됩니다. Taste OS의 온보딩은 *머무름* 을 위해 설계됩니다. 사용자가 다 채우지 않아도 분석은 시작돼요. 다 채우면 더 깊게 들을 뿐이에요.

이 문서가 잘 따라간다면, 7분 후 사용자는 — 양식을 *제출했다는* 느낌이 아니라 — *자기 자신을 누군가에게 처음으로 보여줬다는 느낌*을 갖게 됩니다. 그게 차이의 전부예요.
